## Acceptance criteria

- AC-W2-1 Panel: an assistant panel (drawer on desktop, bottom sheet or full screen on 390px) opened from a header button on every shop page. Keyboard accessible (open, Escape closes, focus returns), labelled. Week 1 pages keep working unchanged.
- AC-W2-2 Trusted component catalog: exactly 6 to 8 components we own, referenced by name only: ProductCard, ProductGrid (or Carousel), CompareTable, CartSummary, QuantityStepper, FilterChips, CheckoutHandoff, OrderStatusCard (pick 6 to 8). Each has a strict zod schema for its props. The agent never supplies HTML, JS, URLs to arbitrary hosts, class names, styles or event handler code.
- AC-W2-3 A2UI messages: the panel consumes A2UI protocol messages (use @a2ui/react and @a2ui/web_core as in the spike, or a documented subset if the library does not fit; record the choice). Every incoming message is validated against a schema before render. Unknown component names, unknown or invalid props, oversized payloads, and too-deep trees are rejected and rendered as a safe fallback card ("I could not show that"), with a redacted diagnostic in the dev log only.
- AC-W2-4 Data binding: product references are by product id only; the renderer looks up name, price and stock from the server catalog. Agent-supplied prices or names are ignored, so a message cannot show a fake price.
- AC-W2-5 Actions: the only A2UI actions are a fixed allowlist (for example add_to_cart, set_quantity, remove_from_cart, apply_filter, compare, show_cart, go_to_checkout, show_order). Each has a validated payload and a server-side handler that reuses week 1 cart logic. go_to_checkout only navigates to /checkout (client navigation) and never calls payAction or any Daraja code. No action named pay, confirm_payment, stk or similar exists, and any such action in a message is rejected.
- AC-W2-6 Pay-tap-only rule (extends AC-5): STK still fires only from the Pay tap on /checkout. Guard tests are extended: static scan that no file under the assistant, A2UI, planner or action-handler code imports lib/daraja, app/checkout/actions or references initiateStk or payAction; runtime test that drives every A2UI action handler with valid and hostile payloads and a spy adapter and asserts initiateStk is never called; e2e check that using the panel (including go_to_checkout) creates no order until the shopper taps Pay.
- AC-W2-7 Planner: a deterministic local mock planner is the default (DUKA_ASSISTANT_MODE=mock). It maps shopper text to A2UI messages (search, show category, compare two items, show cart, change quantity, go to checkout, order status). No network, no keys, no spend. Any real-model path is optional, behind DUKA_ASSISTANT_MODE=model, off by default, uses no paid keys, and is not exercised in tests. Planner output passes through the same validator as any other message.
- AC-W2-8 Injection safety: tests where product text, shopper text, or planner output tries to (a) render a pay or STK action, (b) inject HTML or script, (c) use an unknown component, (d) override price, (e) point a link off site. All are rejected or neutralised, and the fallback renders. Text props are rendered as text, never as HTML.
- AC-W2-9 Limits (front-end scope): message size, component count and tree depth caps in the validator. Server rate limits are DROPPED (backend hardening is out of scope).
- AC-W2-14 Mock only: the app's adapter selection always uses the mock adapter; DUKA_DARAJA_MODE=sandbox is ignored or refused by the app with a clear log line. Daraja code and the smoke script are kept unchanged and marked PARKED in README and PLAN.md. Week 1 tests that cover sandbox code may stay; adjust only those that assert the app can select sandbox.
- AC-W2-10 UI: uses week 1 visual language. No horizontal overflow at 390 and 1280. Screenshots in evidence/week2/: panel-open.png, components-products.png, components-compare.png, components-cart.png, handoff.png, fallback-rejected.png, plus mobile variants (panel-open-mobile.png at least).
- AC-W2-11 Tests: pnpm test and pnpm e2e both pass, including all week 1 tests (no regressions), guard tests and injection tests.
- AC-W2-12 Installs inside the project only, with .npmrc store-dir=.pnpm-store (gitignored). No remote, push, host, tunnel. Duka env file only, never Enroll's. No secrets in files or logs. No em dashes.
- AC-W2-13 Docs: README updated (panel, mock-only, how to run), PLAN.md rewritten for the front-end playground: Daraja PARKED, plus a shorter revised estimate in days for the rest (more components, WebMCP flag, polish), SELF-EVAL-WEEK2.md filled.
