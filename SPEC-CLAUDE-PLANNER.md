- AC-CP-2 Live gate: the Claude planner may reach the network ONLY when DUKA_PLANNER=claude AND DUKA_ALLOW_LIVE=1 AND ANTHROPIC_API_KEY is set AND NODE_ENV is not "test". DUKA_ALLOW_LIVE stays unset everywhere in this build (scripts, e2e, .env, .env.example shows it commented out).
- AC-CP-3 Network guard: a vitest setup file makes any request to api.anthropic.com (global fetch and the SDK client) throw. A test proves the guard trips. The e2e server runs with the mock client and a network guard too (for example a fetch wrapper in the planner client that refuses when DUKA_ALLOW_LIVE is not 1). Prove zero live calls: count calls to the real client constructor or transport in tests and e2e, and assert 0.
- AC-CP-4 Tool use: the Claude planner sends a Messages API request with tools for search_products, list_products, get_product, view_cart, add_to_cart, update_cart_quantity, remove_from_cart, place_mock_order, list_orders. Tool schemas are JSON Schema in the MCP tool shape (name, description, input_schema), defined once in lib/assistant/tools/ and reused (so week 3 could expose them over MCP or WebMCP). It runs the tool loop (tool_use, then tool_result) with a hard cap on turns (for example 4), max_tokens cap, and a timeout. Tool handlers reuse the week 1 and 2 server logic.
- AC-CP-5 No pay: there is no pay tool. place_mock_order creates a mock order record only if it is the existing safe mock path; it must NOT call payAction, initiateStk or anything in lib/daraja. Prefer: place_mock_order returns a checkout handoff (navigate to /checkout) and the shopper still taps Pay. Guard tests extended: static import chains from the Claude planner and tools never reach lib/daraja or app/checkout/actions; runtime test drives every tool with valid and hostile input and asserts initiateStk is never called.
- AC-CP-6 Output: the model's final answer is a render tool call (for example render_ui) whose input is A2UI component specs plus a reply key. Output is validated by the existing lib/a2ui/validate.ts and the trusted-text rules (reply and headings are keys, not free text; product ids only; no prices, links or paths in strings). Invalid parts are dropped or replaced with the safe fallback card. Free text from the model is never rendered; if the model sends plain text instead of the render tool, show a trusted reply plus fallback.
- AC-CP-7 Fallback: no key, live not allowed, API error, timeout, malformed response, tool loop cap hit, or validation failure gives a regex-planner answer (or the fallback card) with a dev-log diagnostic that never contains the key or raw model text.
